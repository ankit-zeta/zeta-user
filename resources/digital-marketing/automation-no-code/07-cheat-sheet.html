Name Splitting

Full Name → First/Last

Date Formatting

    Error Handling Patterns

    Zapier: Auto Replay

    Settings → Auto Replay: ON
    Failed runs retry: 5 min, 30 min, 2 hr, 8 hr
    Filter: Only replay "Rate Limit" & "Timeout" errors

    Make: Error Handlers

    Add "Error Handler" module to any module
    Types: Break, Resume, Ignore, Custom
    Resume: Provide fallback data → Continue flow
    Custom: Slack Alert → Data Store → Manual Retry

    Rate Limit Handling

    HTTP 429 → Wait: Retry-After header
    Exponential Backoff: 1s, 2s, 4s, 8s, 16s (max 5 retries)
    Queue: Make Data Store or Zapier Queue (beta)

    Partial Failure Recovery

    Scenario fails at Step 5 of 10
    Make: Incomplete Execution → Fix Data → Resume from Step 5
    Zapier: Replay from failed step (if idempotent)

    Dead Letter Queue

    Failed after max retries → Store in Airtable/Sheets
    Fields: Payload, Error, Timestamp, Workflow, Retry Count
    Daily Review: Manual fix → Replay via "Reprocess" workflow

    Monitoring Alerts

    Zapier: Filter by Status = "Error" → Slack/Email
    Make: Scenario Settings → Notifications → On Error
    Custom: Daily Run → Count Errors → Alert if > Threshold

    Rate Limits & Optimization

    Zapier Limits

    Free: 100 tasks/mo, 15 min polling
    Starter: 750 tasks, 15 min
    Professional: 2,000 tasks, 2 min
    Team: 50,000 tasks, 1 min
    Optimize: Combine steps, use Code step

    Make Limits

    Free: 1,000 ops/mo, 15 min
    Core: 10,000 ops, 5 min
    Pro: 40,000 ops, 1 min
    Teams: 100,000 ops, 1 min
    Ops = Module executions (1 scenario = many ops)

    API Rate Limits (Common)

    HubSpot: 100 req/10s (burst), 400/day (free)
    Airtable: 5 req/s/base
    Notion: 3 req/s (avg)
    Slack: 50+ methods, tiered
    Google Sheets: 500 req/100s/user

    Optimization Tips

    • Batch API calls (array input vs loop)
    • Cache lookups (Data Store, Zapier Storage)
    • Filter early (don't fetch what you'll discard)
    • Use webhooks over polling
    • Schedule non-urgent at off-peak

    Testing Without Burning Ops

    Make: "Run Once" with test data
    Zapier: "Test" button + Sample Data
    Both: Dedicated "Sandbox" accounts
    Mock: Use RequestBin/Webhook.site for HTTP

    Cost Control

    Monthly Audit: Tasks/Ops per Workflow
    Kill: Unused, Duplicate, High-cost/Low-value
    Consolidate: Multiple Zaps → 1 Make Scenario
    Negotiate: Annual plans save 20-30%

    Testing Checklist (Before Going Live)

    ✅ Happy Path

    Real trigger data → All steps execute → Correct output in destination

    ✅ Missing Required Fields

    Trigger with empty name/email → Filter/Error handling works → No crash

    ✅ Duplicate Trigger

    Same payload twice → No duplicate records created (idempotent)

    ✅ API Errors

    Destination down / 500 / 429 → Alert sent → Retry works → No data loss

    ✅ Large Payloads

    Many line items / Large files → No timeout / Memory error

    ✅ Edge Cases

    Special chars in names, Emojis, Very long text, Null values, Timezone edge

    ✅ Permissions

    Connected accounts have correct scopes; Token not expired; 2FA not blocking
