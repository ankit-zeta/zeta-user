Console methods, common errors, and step-by-step debugging techniques

Common JavaScript Errors

TypeError: Cannot read property of undefined

You're trying to access a property on something that doesn't exist.

Fix: Add a check: if (obj && obj.property) or use optional chaining obj?.property

ReferenceError: x is not defined

You're using a variable that hasn't been declared.

Fix: Check spelling. Make sure the variable is declared with let/const/var or is in scope.

SyntaxError: Unexpected token

Missing bracket, comma, semicolon, or other syntax issue.

Fix: Check matching brackets. Look at the line number in the error message.

TypeError: x is not a function

You're trying to call something that isn't a function.

Fix: Check if the function name is correct. Ensure the function is imported/defined before use.

CORS Error (Cross-Origin)

Browser blocks requests to a different domain for security.

Fix: Use a proxy, CORS headers on the server, or fetch from your own backend.

Debugging Workflow

Step 1: READ the error message → What type of error? What line number? Step 2: ADD console.log() around the problem area → Print variable values before and after the issue Step 3: USE THE DEBUGGER → Add "debugger;" statement in code → Or set breakpoint in DevTools Sources tab → Step through code line by line Step 4: CHECK THE NETWORK TAB → Are API calls failing? (Red status codes) → Is data coming back as expected? Step 5: SIMPLIFY → Comment out code until the error disappears → Add code back one line at a time

💡 Golden Rule of Debugging

If you've been stuck for more than 30 minutes, take a break. Walk away. Come back with fresh eyes. Most bugs are simple mistakes you're too close to see.
